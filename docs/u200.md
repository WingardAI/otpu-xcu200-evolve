# openTPU on the Alveo U200 (XCU200)

openTPU runs on the U200 as a **Vitis RTL kernel**: the same RTL as the card target
(`rtl/`), packaged into an xclbin and loaded over PCIe with XRT into the shell of
`xilinx_u200_gen3x16_xdma_2_202110_1` (XDMA + four DDR4-2400 MIG controllers), part
`xcu200-fsgd2104-2-e`.

The platform is selected by a target file, so everything else -- compiler, ISA simulator,
Verilator model, tests, host API -- is shared with the other targets:

| file | what it describes |
|---|---|
| `targets/u200-vitis.toml` | S=2, TMEM 32K words, 2 GiB per channel per slice, core at 150 MHz from ap_clk 300 MHz |
| `targets/u200-vitis-moe.toml` | S=1, TMEM 64K (the MoE / Qwen3.5-35B-A3B image) |
| `rtl/boards/u200-vitis/otpu_u200_kernel.sv` | `OtpuKernel`: registers + a scratch AXI master (bring-up) |
| `rtl/boards/u200-vitis/otpu_u200_core_kernel.sv` | `OtpuCoreKernel`: the accelerator (the slices, `otpu_mem_ch`, the AXI bridge) |

### Two ways of using the U200

| target | how the accelerator reaches the card |
|---|---|
| `u200` (`targets/u200.toml`, platform id 3) | the **native board flow**: XDMA Gen3 x16 over the card's character device, the LiteDRAM DDR4 core and the board top under `boards/bcu1525` (the U200 is the same package/pinout as the BCU1525, different device). Development builds at 100 MHz / DDR4-1600. |
| `u200-vitis` / `u200-vitis-moe` (platform id 4) | the **Vitis RTL kernel**: the core packaged as an xclbin (`boards/u200-vitis/`), loaded over PCIe with XRT into the official `xilinx_u200_gen3x16_xdma_2_202110_1` shell, DRAM through `otpu_native_dram`'s AXI bridge instead of LiteDRAM, at 150 MHz from ap_clk 300 MHz |

This document follows the second (the RTL-kernel port); `docs/bcu1525.md` and
`docs/board.md` describe the native board flow the first target shares with it.

## Build

```sh
source /path/to/Vitis/2024.2/settings64.sh
boards/u200-vitis/build.sh          # OtpuKernel  -> boards/u200-vitis/build/OtpuKernel.xclbin
boards/u200-vitis/build_core.sh     # OtpuCoreKernel -> .../build/OtpuCoreKernel.xclbin
```

`build.sh` packages the kernel with `vivado`/`package_xo`
(`boards/u200-vitis/scripts/package_kernel.tcl`, `kernel.xml`) and links it with `v++`; the
constraints are in `boards/u200-vitis/constraints/` and the clock converter IP in
`boards/u200-vitis/ip/`. Environment: `OUT` (build directory), `JOBS` (`v++` jobs),
`KERNEL_MHZ` (300 for `build.sh`, 150 for `build_core.sh`), and for `build_core.sh`
`OTPU_NS` (2 slices, 1 for the MoE image) and `OTPU_TMEM_WORDS` (32768, 65536 for the MoE
image), which patch the kernel top's parameters.

## Run

The host loads the xclbin when `OTPU_XCLBIN` names it; without that variable the driver uses
the card's XDMA path. Registers go through `xrt::ip`, DRAM through `xrt::bo` (2 GiB per
channel per slice, the buffer's base passed as a kernel argument); see
`opentpu/host/xrt.py`.

```sh
export OTPU_XCLBIN=boards/u200-vitis/build/OtpuCoreKernel.xclbin
export OTPU_TARGET=u200-vitis-moe        # or u200-vitis (S=2)
otpu-smi                                  # device is up, clocks, DRAM
otpu-chat --model qwen3 --backend board   # a model on the U200
python3 -m pytest -q tests/test_target.py tests/test_board.py
```

`otpu-chat`, `otpu-serve`, `otpu-smi`, `otpu-lens`, `otpu-diag` and `otpu-selftest` are the
same for every target; the register map and the ISA are in `docs/isa.md`, the memory path
(the shell's MIG instead of LiteDRAM, the AXI bridge, `otpu_mem_ch`) in `docs/board.md` and
`docs/isa.md`'s "Memory", and the architecture in `docs/dataflow.md`.

## What differs from the card target

* **Memory**: the shell owns the MIGs and their calibration (`mem_ctrl = "shell"`,
  `hostcal = false`); the accelerator reaches DRAM through `otpu_native_dram`'s AXI bridge
  (`rtl/mem/otpu_axi_dram.sv`) instead of the LiteDRAM core.
* **Host path**: `xrt::bo` buffers instead of the XDMA character device, `xrt::ip` instead of
  the BAR's register file; the buffer bases are kernel arguments
  (`channel_bytes = 2 GiB`, `channel_phys_bytes = 16 GiB`).
* **Clocks**: ap_clk 300 MHz from the shell, the core at 150 MHz (`core_mhz`), the DDR4
  controllers at 2400 MT/s.
* **Slices**: `u200-vitis` is S=2; `u200-vitis-moe` is S=1 with 64K TMEM for the models that
  stream experts.
